# 百事AA Excel兼容导入（第一阶段）

支持将百事AA导出的17列FULL格式Excel导入BeeCount Cloud。第二阶段的百事AA格式导出尚未实现。

## 使用入口

沿用账本菜单的“导入”页面 `/app/import`。提供“原有账单导入”和“百事AA兼容导入”两种入口，默认原有导入。两者共用渐变来源卡片，原有BeeCount和通用CSV/TSV/Excel解析及字段映射流程保留。百事AA入口的文件选择器筛选xlsx，上传后以服务端实际识别结果切换对应来源说明，不强制更改解析规则。切换入口只清空尚未执行的预览，不写入账本。上传百事AA的17列FULL格式xlsx，自动识别后展示来源账本、交易预览、金额、分类、图片数及错误。必须明确选择已有账本，或选择“创建新账本”并核对名称；源账本名称只是建议，不会据此自动匹配已有账本。导入完成后切换至目标账本。

单文件上限沿用10MB、账单上限50000行；解压后的Excel内容限制80MB。解析token保存在进程内，30分钟后失效，重启也会失效，重新上传即可。导入状态依赖单进程内存；多worker不共享token及执行锁，不能把本实现视为分布式幂等方案。

## 映射与限制

| 百事AA列 | BeeCount含义 |
| --- | --- |
| 交易类型、交易金额 | 普通支出或收入，十进制金额；允许合法零金额 |
| 日期 | 按百事AA国内导出的UTC+8墙钟转换为UTC，缺失的秒数不能恢复 |
| 类别、标签 | 一级、二级分类；百事AA标签在本格式中不是独立交易标签 |
| 账户 | 账户名称 |
| 描述 | 原备注，加来源账本和创建/付款/分摊人文字说明 |
| 工作表图片 | 按OOXML锚点实际行关联的PNG/JPEG附件 |
| 创建者、付款人与分账人及其金额 | 校验单人关系；不映射成系统用户ID |
| 账本名称 | 来源信息及新账本名称建议 |

接受单工作表、单一源账本、单人单币种普通收支，支持明确ISO代码CNY、USD、JPY、HKD、MOP（澳门币，不是AUD）。文件内币种必须一致，原金额与默认币种金额须相等；已有目标账本必须同币种，新账本按来源币种创建。币种代码可去首尾空格并转大写，但不猜测“澳币”或$等含糊名称。退款、转账、复杂AA/多人、币种折算、非空报销或统计标记、额外非空列、无法关联图片均阻断导入，不静默忽略。

通用写入按名称和收支类型匹配分类。源文件若一级/二级同名，或二级同名但属于不同父级，只给有歧义的二级名称加`（父类）`，保留原父级，并逐行显示警告。目标中已有分类若层级或父级不同则阻断；应核对映射或使用新账本，不能自动合并。当前规则不是百事AA全量格式无损往返承诺。

## 去重与事务

百事AA导入必须先点击“核对重复记录”，再点击“确认并开始导入”。核对弹窗将记录分为“待新增”“匹配已有”“需要确认”，逐行展示处理方式和已有候选；每页25行，未处理项按全文件计数。存在未选择的疑似项时不能继续。原有BeeCount与通用格式保留既有流程。

推荐“去重”策略。服务端保存独立的来源记录，依据规范化的原始17列、UTC时间和图片内容SHA-256生成指纹，不依赖新文件哈希或行号。重新导出或行位置变化仍可匹配；相同指纹按已有交易数量一对一分配，例如已有两笔相同消费，本次三笔只匹配两笔，第三笔不会自动被吞掉。目标账单被人工修改时，原来源关联仍保留；被删除的交易不再参与匹配。账单内容相同不等于拥有源系统唯一ID，用户仍应核对笔数。

缺少精确来源依据、但类型/币种/交易时间相同，或类型/币种/金额相同且时间在前后7天内的记录列为疑似项，必须选择“作为新账单导入”，或“跳过并关联”某条候选。不会自动覆盖金额、备注、日期等已有字段；关联后保存新的来源指纹，供后续重导匹配。时间修改候选仅提示，不自动跳过；超过7天或同时改金额等无法匹配的记录仍可能列为待新增，不能视为百分百自动识别所有改账。同批次每条已有记录只能被一条来源记录关联，人工选择冲突会拒绝确认，必须改为新增或选择另一候选。每行最多展示20条候选并提示总数；没有合适的候选时应返回账本核查，不应随意关联。全部导入策略仍需核对确认，并明确提示匹配记录也会新增。

旧版缺少来源表的导入记录：同一原文件仍可凭固定syncId识别，成功跳过后补建来源关联；重新导出的文件只能依靠疑似候选人工核对，不能追溯恢复不存在的源ID。首次升级后，优先使用原导入文件补齐关联。

核对是只读预览；确认版本包含文件、目标、映射、策略、标签和当前账本内容。执行前及取得写入锁后再次校验，目标或配置变化则拒绝执行并要求重新核对。修改映射或目标、重新打开核对页都会撤销上次确认。

API：`POST /api/v1/import/{token}/review`返回分页核对；提交`revision`和`decisions`（按源行号，action为insert或skip，skip指定match_id）保存选择；所有未决项完成后携带`confirm: true`确认，再调用原execute接口。只允许上传用户操作，目标仍需写权限。缺少确认、版本过期、尚有未决项分别返回409及`IMPORT_REVIEW_REQUIRED`、`IMPORT_REVIEW_STALE`、`IMPORT_REVIEW_UNRESOLVED`。取得写入锁后发现变化通过SSE error返回。

新账本、成员、交易、来源关联、附件记录及SyncChange在一个数据库事务内提交。失败时回滚数据库，并清理本次新建的图片文件；复用的旧文件不删除。同token执行锁防止双击/重连重复执行，提交后立即消耗token。token只归上传用户所有，导入目标必须具备交易写权限。

附件使用现有`ATTACHMENT_STORAGE_DIR`和`ATTACHMENT_MAX_UPLOAD_BYTES`；目录按账本所有者/账本/哈希前缀组织，交易携带现有cloudFileId等附件引用。新增数据库迁移`0021_import_source_records`，只创建来源表与索引，不改写既有账单。来源表包含原始账单字段，须与财务数据库同等保护并纳入备份；不新增环境变量、外部服务或后台任务。降级迁移只删除来源表，不删除账单，但会丢失跨文件匹配依据。生产回退前应先备份，不自动降级数据库。数据库和文件系统并非同一种事务：应用异常和取消有清理逻辑，但进程被强制杀死时仍可能留下孤立图片，维护时应按现有附件清理机制处理。

## 代码边界

- `src/services/compatibility/baishi_aa/`：格式识别、重复金额列按位置处理、业务限制、图片和目标分类校验，解析器输出标准ImportData；独立review.py负责只读匹配与同事务来源暂存。
- `src/services/import_data/parser.py`：xlsx分发；其余原生与通用格式仍复用原流程。
- `schema.py`：最小来源/错误/附件元数据；`cache.py`：目标及执行状态。
- `execution_support.py`：可回滚的新账本和附件暂存。
- `src/routers/import_data/endpoints.py`：复用预览、权限、事务写入、同步及SSE。
- `frontend/apps/web/src/components/import/ImportSourceCard.tsx`：两种导入共用的来源卡片；ImportPage处理入口切换、目标选择与流程。
- `tests/compatibility/test_baishi_aa.py`：合成Excel和隔离SQLite测试，真实财务文件不进入Git。

没有引入动态插件系统；适配器是编译期独立模块，后续上游更新主要核对上述接入点。第二阶段可在同一兼容目录增加writer，但须先核实百事AA真正接受的导入模板，不把“能生成xlsx”当作“能导回百事AA”。

## 验证与部署

兼容测试使用合成Excel和隔离SQLite，覆盖原有格式导入、字段映射、金额与时区、分类层级、图片关联、同文件去重、失败回滚、跨文件数量匹配、疑似项选择、未决分页、来源回滚、旧数据兼容、过期确认及写入权限。真实账单、用户配置和部署记录不应提交到源码仓库。

后端验证：`pytest tests -q`。前端在`frontend/`目录执行`pnpm --filter @beecount/web test`和`pnpm --filter @beecount/web build`。部署方法参见[部署指南](DEPLOYMENT.md)，升级前备份数据库、附件和认证密钥，并先在隔离实例验证。移动端同步及图片显示需在实际客户端另行验收。
