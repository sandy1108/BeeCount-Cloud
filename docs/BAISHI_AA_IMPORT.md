# 百事AA Excel导入（个人定制，第一阶段）

状态：本地实现和隔离验收；尚未部署正式实例。目标是BeeCount Cloud，不是Beancount文本账本项目。第二阶段的百事AA格式导出尚未实现。

## 使用入口

沿用账本菜单的“导入”页面 `/app/import`。提供“原有账单导入”和“百事AA兼容导入”两种入口，默认原有导入。两者共用渐变来源卡片，原有BeeCount和通用CSV/TSV/Excel解析及字段映射流程保留。百事AA入口的文件选择器筛选xlsx，上传后以服务端实际识别结果切换对应来源说明，不强制更改解析规则。切换入口只清空尚未执行的预览，不写入账本。上传百事AA的17列FULL格式xlsx，自动识别后展示来源账本、交易预览、金额、分类、图片数及错误。必须明确选择已有账本，或选择“创建新账本”并核对名称；源账本名称只是建议，不会据此自动匹配已有账本。导入完成后切换至目标账本。

单文件上限沿用10MB、账单上限50000行；解压后的Excel内容限制80MB。解析token保存在进程内，30分钟后失效，重启也会失效，重新上传即可。维持当前单进程部署；多worker不共享token及执行锁，不能把本实现视为分布式幂等方案。

## 映射与限制

| 百事AA列 | BeeCount含义 |
| --- | --- |
| 交易类型、交易金额 | 普通支出或收入，十进制金额；允许合法零金额 |
| 日期 | 按百事AA国内导出的UTC+8墙钟转换为UTC，缺失的秒数不能恢复 |
| 类别、标签 | 一级、二级分类；百事AA标签在本格式中不是独立交易标签 |
| 账户 | 账户名称 |
| 描述 | 原备注，加来源账本和创建/付款/分摊人文字说明 |
| 工作表图片 | 按OOXML锚点实际行关联的PNG/JPEG附件 |
| 创建者、付款人与分账人及其金额 | 校验单人关系；不映射成系统用户ID |
| 账本名称 | 来源信息及新账本名称建议 |

首期仅接受单工作表、单一源账本、单人CNY普通收支，目标账本也须CNY。退款、转账、复杂AA/多人、币种折算、非空报销或统计标记、额外非空列、无法关联图片均阻断导入，不静默忽略。

通用写入按名称和收支类型匹配分类。源文件若一级/二级同名，或二级同名但属于不同父级，只给有歧义的二级名称加`（父类）`，保留原父级，并逐行显示警告。目标中已有分类若层级或父级不同则阻断；应核对映射或使用新账本，不能自动合并。当前规则不是百事AA全量格式无损往返承诺。

## 去重与事务

推荐“去重”策略。百事AA采用完整文件SHA-256和原始行号生成固定交易syncId，重复上传同一文件到同一账本会跳过已有行；同额、同时间的不同原始行保留。重新导出或编辑后的文件哈希不同，重叠区间须人工核对，不能自动跨文件去重。“全部导入”会显式创建新交易，不承诺后续去重。

新账本、成员、交易、附件记录及SyncChange在一个数据库事务内提交。失败时回滚数据库，并清理本次新建的图片文件；复用的旧文件不删除。同token执行锁防止双击/重连重复执行，提交后立即消耗token。token只归上传用户所有，导入目标必须具备交易写权限。

附件使用现有`ATTACHMENT_STORAGE_DIR`和`ATTACHMENT_MAX_UPLOAD_BYTES`；目录按账本所有者/账本/哈希前缀组织，交易携带现有cloudFileId等附件引用。不新增环境变量、数据库表、外部服务或后台任务。数据库和文件系统并非同一种事务：应用异常和取消有清理逻辑，但进程被强制杀死时仍可能留下孤立图片，维护时应按现有附件清理机制处理。

## 代码边界

- `src/services/compatibility/baishi_aa/`：格式识别、重复金额列按位置处理、业务限制、图片和目标分类校验，输出标准ImportData，不写数据库。
- `src/services/import_data/parser.py`：xlsx分发；其余原生与通用格式仍复用原流程。
- `schema.py`：最小来源/错误/附件元数据；`cache.py`：目标及执行状态。
- `execution_support.py`：可回滚的新账本和附件暂存。
- `src/routers/import_data/endpoints.py`：复用预览、权限、事务写入、同步及SSE。
- `frontend/apps/web/src/components/import/ImportSourceCard.tsx`：两种导入共用的来源卡片；ImportPage处理入口切换、目标选择与流程。
- `tests/compatibility/test_baishi_aa.py`：合成Excel和隔离SQLite测试，真实财务文件不进入Git。

没有引入动态插件系统；适配器是编译期独立模块，后续上游更新主要核对上述接入点。第二阶段可在同一兼容目录增加writer，但须先核实百事AA真正接受的导入模板，不把“能生成xlsx”当作“能导回百事AA”。
