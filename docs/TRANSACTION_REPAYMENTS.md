# 交易详情的关联回款

支出3000，关联三笔各750的收入后，详情显示原支出3000、已收回2250、最终承担750。原始收入和支出仍是独立流水，首页、分类和雪季同比继续按原现金收支统计。

## 使用与限制

先记录收入，再打开对应支出详情，选择“关联收入”。候选支持备注/分类搜索和分页；确认前可填写独立说明，退款、报销、分摊回款仅为快捷文字。说明默认空，不修改原流水备注，不参与算法。收入详情可反向查看原支出；解除只移除关系，保留两边流水。

首版只允许同账本、同原币种、正金额、同五月年度的支出与收入。单收入只能关联一笔支出，回款合计不得超过原支出，不拆分、不截断、不猜汇率。排除收支统计的流水仍可关联，详情明确标识；不改变其统计标记。不自动推断历史关系。

五月年度沿用统一`ski_season_range`：本地5月1日至次年5月1日半开区间。首次关联继承统计下钻保存的`tzOffsetMinutes`；普通交易详情取浏览器本地偏移，与首页一致。组内保存首次偏移，后续新增和编辑校验复用它；另一设备传入不同偏移不能更改既有关联组。全部解除后新建关系重新确定偏移。不是固定北京时间或新增账本时区。

## 独立扩展与写入保护

迁移`0024_transaction_repayments`只新增`transaction_repayments`表，按账本内部ID与收入sync ID唯一定位，另存支出sync ID、偏移、说明和创建信息。交易字段和原金额不迁移。原币使用交易amount，不以native_amount或今日汇率抵扣。

接口：

- `GET /read/ledgers/{id}/transactions/{tx}/settlement`：双向摘要及读写权限。
- `GET /read/ledgers/{id}/transactions/{expense}/repayment-candidates`：明确传入偏移，分页、搜索符合条件的收入。
- `POST /write/ledgers/{id}/transactions/{expense}/repayments`：income_id、tz_offset_minutes必填，note可空。同关系同说明重复请求幂等；变更说明先解除再建立。
- `DELETE /write/ledgers/{id}/transactions/{expense}/repayments/{income}`：显式解除，重复执行不删流水。

复用现有账本权限：Owner/Editor可写，Viewer只读，非成员/已撤销权限不可访问。新接口与原Web读写接口采用相同scope策略。

`services/settlements.py`集中约束。投影upsert/delete、Web批量、旧手机增量同步、账本删除及旧协议删除标记、账本币种修改、快照重建均校验。仅阻止会破坏关系的修改；备注/分类、仍有效的金额或日期修改可以保存。批量删除逐项返回冲突，合法项继续；同步批次失败整批回滚。返回`SETTLEMENT_CONFLICT`及可操作说明，Web保留具体错误。

D写接口在PostgreSQL使用账本事务锁；SQLite先取写锁再读，收入唯一约束与事务内合计校验防重复和超额。Web本位币重算前固定关联交易原有隐含币种，避免逐条重算的中间状态误判为跨币种。

关联不作为新同步实体发给旧移动端，旧端省略关系字段不会清空它。独立`repayment_change`通知供Web重新读取；Web重新聚焦也刷新，移动端沿用既有事件白名单。Android/iOS/鸿蒙入口仍待开发，不代表已做设备实测。

## 备份与恢复

完整数据库备份包含新表。服务端逻辑备份从当前projection生成交易快照，并保存版本化`cloudRepayments`扩展；恢复在同一事务校验并恢复关系，不向旧客户端发送该扩展。损坏扩展、重复收入、跨季、异币或超额等恢复失败整批回滚。

旧客户端上传的快照没有关系扩展时，保留当前关系并在清表前校验完整替换集合；不能恢复出悬空或无效关系。带扩展的备份若会替换当前不同关系，须先显式解除，不能静默抹除。备份本位币与当前账本不一致且含关联时拒绝恢复。只导出旧CSV/Excel或旧手机数据库不包含Cloud关系，不能用于完整往返恢复；百事AA关系导出不在本批。
